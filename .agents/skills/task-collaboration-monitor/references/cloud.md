# 云端执行侧清单

适用于已有授权的云端 Dot 或 Codex Cloud 任务。先核原项目、任务、工作流、委派和执行引用。将平台关联 ID 与原生会话或任务 ID 对应；共享账号的 `whoami` 仅证明账号权限。

1. 在实际执行端发现工具。用 `whoami` 核项目及来源；根据[查询](query.md)查原任务和工作流。有 `execution_id` 参数且已知实例时用它限定查询，读回 `relationships.upstream` 和 `relationships.downstream` 中与原委派相符的记录。缺参数、工具、真实关系或读权限时记录缺项。
2. 按[上报](report.md)保存原 `source_id`、`batch_id`、`event_id`，关联原任务、工作流和执行实例。工作开始、实质进展、阻塞及回件各用真实证据和下一动作。共享 OAuth 只能自报；独立执行来源令牌仅在已配置且匹配范围时使用。将凭据留在宿主管理渠道。自报进入原任务时间线。原宿主或 Router 负责实际派发、接手、停止和接续，工作流图由原维护来源更新。
3. 成功时核同一批次的持久回执，确认接受与重复 ID 合计覆盖原事件。超时先查原批次。查询方沿原任务读回同一事件、证据类别和上下游，页面核对实际正文。来源陈旧和缺失关系按实记录。
4. Cloud 启动前由原 Router 冻结输入、预期提交和唯一派发者，记录原生任务 ID、实际检出及实际工具调用。启动技能清单若提供来源路径，核对是否落在实际仓库；文件实读及引用另留证。调用结果未知时沿原请求对账。运行中间若无法查询或上报，在同一原生任务的回件中保留证据、缺口与回程责任，供获准接收者接续。

App 刷新、实际加载、真实执行关联、事件写入、持久回执、原任务查询和页面可见都需要对应证据。原生工具缺失时按已获准入口报告缺口。用户可见的进度、取消、读取和业务验收沿原记录分别核证。
