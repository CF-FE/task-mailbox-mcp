# 单件目标运行准入与撤销

本页是 `DELEGATE_GOAL` 的宿主维护流程，外部请求与结果仍遵循 [SPEC](../SPEC.md#逐件目标交办的数据合同)。Task Mailbox 保存数据，Mac 桥校验原件并持久补传；目标运行入口、负责人联系及组织工具按 Herdr 仓的[目标合同](https://github.com/CF-FE/herdr-4-codexcloud/blob/main/docs/goal-handoff.md)和[运行准入说明](https://github.com/CF-FE/herdr-4-codexcloud/blob/main/docs/goal-runtime.md)独立维护、发布与验收。两仓不共享运行导入或软链接。

本页不授予部署、凭据配置或真实任务派发权。离线实现和合成测试可以完成交付；真实启用另按已经明确批准的单件范围执行。公共交接只写固定版本、脱敏证据引用和结论；真实 job、摘要、主体、端点、私有路径、策略、密钥及原始输出保留在宿主受限记录中。下文项目示例均为 `ExampleOrg/example-project` 占位。

## 分层责任与默认关闭

| 层 | 负责的事实 | 不能据此推导的事实 |
| --- | --- | --- |
| Task Mailbox | 原 job/hash 持久化、不可变结果版本、取消请求和精确读确认 | 收件者真实身份、负责人接手、执行停止或业务验收 |
| Mac 桥签名端口 | 精确 grant 下的原件证明、结果结构校验、稳定 event 入 outbox | 负责人原生身份核验、工具执行、任务完成或真实听检 |
| 协调核心与原生适配器 | 当前任职绑定、单件来源授权、唯一动作、可信报告归属 | 仅凭工具名称或声明证明组织工具具备实际能力 |
| 组织工具及其维护者 | 被审核实现中的目标、资产、动作和预算限制，以及各次调用回执 | 用信箱 OAuth、grant 或模型提示代替工具自身授权 |
| 原报告读取方（本单为云端Dot） | 按原 job 查询进展或读取指定版本/hash | 把读确认当作接受未完成业务或交还写权 |

协调员空闲配置保持 `pilot:null`，不启用 `goal_channel_config`。这两个字段属于协调员配置；桥端 `coordinator-port.json` 仍只接受其原有 schema。桥端没有可选端口配置时只运行原收发；探测配置使用 `probe-` key 与空业务 grants。新增目标源码或安装包不会把这些状态变成业务准入。

项目由负责人组织。云端Dot可指派验收者，默认由项目负责人验收。云端Dot发起交办后可离线，负责人按本地已受理的原单和有效授权推进。项目验收与摘要送达分别记账，网络恢复后原 collector 继续补传。云端Dot可查原 job 的结果或 GitHub Project 的里程碑，日常无需主动确认已读。

## 单件启用顺序

以下顺序只在取得相应维护与该件运行授权后执行。若某一步缺证据，记录缺少的具体原件；不要借已连通的信箱绕过它。

1. **固定版本和基线。** 分别核对桥与协调 runtime 的正式提交、安装摘要和接口兼容性。保留原 OAuth、source/consumer、单一网络写者、台账、游标、历史结果及其他项目授权。先在隔离环境验证；不要从临时 checkout 或合成工具夹具直接启用真实任务。
2. **核定来源与现任负责人。** 宿主维护方独立核读原始发送回执、原生发件主体、正式 Project item 和 Issue/draft，再核当前任职主体、原生 endpoint 及 generation。证据须绑定同一 job/hash 和任务；文本中的 sender、recipient、角色名、共享账号与可打开 socket 都不能填充这份证明。原端无法核实时保持未准入。
3. **冻结目标包。** 固定 job、request、idempotency、正式任务引用、tracking、payload hash、范围、允许动作、验收标准、检查点及期限。工作身份使用规范 Issue URL，例如 `https://github.com/ExampleOrg/example-project/issues/1`，或原 draft ID；不能靠别名、改措辞、换 ID 重派同一工作。预算保持 `dispatch_attempts=1, production_writes=0, audio_generations=0`。
4. **审核实际运行能力。** 确认固定原生版本、原线程、实际生效配置及该件配置闭包摘要；核真实组织工具实现和动作到工具的映射，以及每个工具的资产范围、现任目标和零生产／音频预算。宿主须逐项比对本单原生策略、能力清单和 stdio 工具实际加载的 policy：项目、request、job/hash、现任身份／endpoint／代次、授权引用、工作键、范围、动作和期限一致，工具角色及子联系预算落在本单授权内。即使文件摘要正确，错单或错角色也须在恢复线程或启动工具前拒绝。具名 profile、允许列表、能力清单或 `HOST_ATTESTED` 预检回执不能单独证明工具可用。旧只读查询通道、全部工具关闭、占位 MCP 与任意 shell 均不能承接目标交办。
5. **准备精确授权，保持执行关闭。** 先让协调员保持 `pilot:null`，将待启用原生策略和能力证明准备在独立私有文件中，尚不从活动配置引用。桥的业务 grant 必须显式指定 `request_kind:"DELEGATE_GOAL"`，精确绑定原 job/hash、来源、任务、recipient、report_route 和协调员；仅给必要的 `verified_job`、`lookup_report`、`enqueue_result` 操作。协调来源 grant 另须明确允许 `submit_goal`，原 `submit` 或 `QUERY_BLOCKER` 不包含它。探针 key 不能业务使用；不得把 `transport_probe` 与目标 grant 混合。
6. **最后打开该件入口。** 在该件批准的窗口内，回读上述全部绑定一致、来源仍有效、负责人仍是原代次、目标未取消且未过期，再由维护者将协调配置原子切换到精确 pilot，并同时引用已审核的 `goal_channel_config`。pilot 仅含该件 `project_id/job_id/request_id/payload_hash`。在此之前不执行目标 pump；配置引用和 pilot 不能先后暴露出不一致的可执行状态。沿原唯一 pump 保存真实受理或拒绝回执；已有定时 pump 时不另开并发手动发送者，不因超时再次派发。
7. **按证据分层回读。** 核原件入台账、原生动作、负责人接手、业务报告及桥 outbox。联网后可核 VPS 已发布的结果；仅在另行约定核验读取时查看原端 ACK。每层保留自己的时间、版本和摘要。到期或结束后由指定维护者收回临时准入，按下文处理在途动作和已有结果。

如果已有该件明确授权，无需为同一项操作反复索要批准；源码升级也不自动扩展已有授权。需要新增权限、换负责人、改资产范围或新的业务动作时，先形成具体变更供原授权方决定。服务连通和网络稳定性只用于判断当前传输结果，不是新增业务授权门槛；无需以长期网络压测作为离线交付的前提。

## 真实组织工具独立于信箱

目标 runtime 的 stdio 工具为 `goal_context`、`read_review_evidence`、`coordinate_independent_review` 和 `read_coordination_report`，实现与准入归协调员仓。它们不是新增的 Mailbox MCP 工具。桥 grant 只控制原件读取、结果查回和入队，不授予这些工具新的资产、目标或原生联系权限。

原线程仍由既有控制入口保管。恢复前须只读核实原生线程已有的审批、沙箱、网络和工具策略；单件进程只能在这些边界内收窄能力。不得用可能持久改变原线程策略的恢复命令试探准入。无法核实继承和隔离时，保留未派发并记录缺口。`NOT_SENT` 只说明没有开始业务回合，不能证明此前操作没有改变线程策略。

原生新读取进程的 idle 不证明旧入口已交还写权。负责人及可选审者还需明确的原控制入口独占/交还审阅证据，绑定原线程和本单，带观察时间及短期有效期。该证明属于宿主准入，不是自动实现的跨进程锁；缺失或冲突时不得启用。短期独占证明过期不会成为重派原动作的理由，已发生动作仍沿原引用只读对账。

独立审者 backend 缺省没有 reviewer，应回报 `BLOCKED`。启用既有审者的一次组织联系，须另核合法任命、与制作方的独立性、精确 endpoint、channel policy 摘要和资产范围；宿主另行明确批准 `review_contact_attempts=1`，缺省为 `0`。原目标的 `dispatch_attempts=1` 不包含这份子联系许可；不能把该字段加进原 goal budget 或桥 grant。该联系只使用已绑定审者，不改项目负责人，也不授予审者递归派发权。

工具可读取受审的 JSON/text、协调证据复核，没有 WAV 播放或音频感知入口。本版受限 v2 原生通道及子工具均拒绝 `independent_listening` 的 `COMPLETED`，不把父负责人或子审者对听辨方法的自述当作实际听检。它能推进核查和报告缺口，不能验收真实听检完成；需要合法听辨执行入口与独立原件，缺少时报告 `BLOCKED`。安装或测试这组工具不自动启用 reviewer、创建凭据、修改安全配置或形成真实派发；这些动作必须作为具体单件准入分别核准并留证。

## 来源证明与 TTL 的实际限制

| 项目 | 当前检查 | 限制与维护责任 |
| --- | --- | --- |
| 信箱 OAuth 与 `whoami` | 证明服务识别的授权账号 | 不签发某个云端线程、角色或 Project item 的身份；来源须带外核准 |
| 桥 grant / 原件证明 | 按 job/hash 及冻结的来源、任务、路由、类型核验；当前请求使用当前策略 | 业务 grant 没有通用 `expires_at` 或 TTL 字段，也不会定时自动删除。不要向 schema 添加未支持字段或声称已经自动失效 |
| 本机 HMAC | 每连接新 challenge，签名覆盖请求与响应 | 防止跨连接复用旧消息，不证明业务来源新鲜、密钥有效期或原端已经停止 |
| `transport_probe.expires_at` | 只约束独立连通性探针的原件读取及首次新增结果 | 不能移作 `DELEGATE_GOAL` 的业务 TTL；已持久探针结果仍按原规则查回与补传 |
| 目标 `deadline` / `next_check_at` | 核心控制新受理、新动作和新业务观察；桥校验时间结构与报告一致性 | 不是运行进程的强制终止计时器；历史有效结果仍可补传，不通过改时间重写原件 |
| 原生策略 / 能力清单的 `expires_at` | 原生入口在规定的准入／执行点检查单件有效期与配置摘要 | 检查不是后台撤权服务；过期、变更或缺失时停止新的原件读取／导出，已有动作的实际停止另核。新鲜度和在途收尾由维护者分别取证 |

TTL 不会自动补足来源证明。记录原件观察时间、核验人／维护角色和有效范围；过期或当前身份无法核实时，停在现有任务上处理。对同账户中能读取私有文件的任意进程，`0600` 文件并不提供多租户隔离；需要相应的宿主隔离才能建立更强边界。不得把密钥内容、完整环境或原生会话正文放进公共验收记录。

## `UNKNOWN` 只对账原任务

固定 job、payload hash、request、action、event、核心版本和原生回合引用。缺少确切结果时保存 `UNKNOWN` 或具体等待原因；重启、断线、等待超时、错误摘要和读取失败都不是生成替代任务或第二次原生动作的依据。

| 观察 | 可作出的结论与下一步 |
| --- | --- |
| `get_job` 返回身份和摘要均一致的原件 | 沿原 job 继续查询；同 ID 异内容是冲突，不能覆盖 |
| 对准确 job 的受信响应明确给出 `NOT_FOUND` | 仅证明该信箱在该次查询时没有该 job；尚须已有首发授权，才可提交同一冻结包。它不证明其他渠道没有工作 |
| 外层 `INVALID_ARGUMENT`、`INVALID_REQUEST`、空列表、超时或无法核验的响应 | 不能推断 `NOT_FOUND` 或未提交。保留原 ID，核参数、工具错误语义及原回执；不换 ID 试投 |
| `verified_job` 返回 `UNAVAILABLE` | 本桥当前未能提供这份可信原件；可能是未保全或证明不匹配，不能当作 VPS 缺件 |
| `lookup_report(job_id,event_id)` 返回有效签名的 `null` | 仅证明该桥本机当前没有这个精确事件。先用协调核心已持久的同一结果对账，允许范围内重传原事件；不重新联系负责人 |
| enqueue 确认丢失或上传 ACK 丢失 | 查原 event 和原 job 的结果版本/hash。只补传相同内容及相同稳定 event，不另做结果或重派 |
| 原生动作已经持久登记但回合结果不明 | 沿原 action/线程/回合做受控只读恢复；缺引用时保持未知，不用新回合代替恢复 |

服务将缺记录映射为 `NOT_FOUND`，参数拒绝映射为 `INVALID_REQUEST`；上层客户端还可能重新包装错误，必须保留其实际证据边界。空事件筛选也不能证明未知别名或其他通道没有在途工作。真实组织工具对自己可能已经发出的动作同样保留原调用标识和 UNKNOWN，不由信箱代为重试业务。

## 结果进入 outbox 后的撤销责任

`request_cancel` 只登记取消请求。撤销准入、阻止新动作、停止已有动作、回传已发生事实和业务验收是不同责任，不能用一个状态覆盖。

核历史时优先使用已经留存的非正文证据，如原 event、精确版本、摘要和回执。撤销或到期后，再通过 `verified_job` 取出完整任务、读取受控资产或向新接收方导出原件，仍须有当前有效且覆盖该对象和接收方的授权；不能借“只读对账”延长原许可。业务 grant 没有自动 TTL，由宿主维护者及时收窄或撤回。

桥在处理请求时加载策略快照；随后撤 grant 不是对已进入处理中的请求进行原子取消。维护者须核这次请求的最终入队状态，不能仅凭配置已删除断言没有新增结果。

| 所处阶段 | 负责方及操作边界 |
| --- | --- |
| 尚未派发 | 宿主维护者关闭该件 pilot 及对应原生入口，撤回该件 grant；核实没有已持久动作。保留原任务及证据 |
| 原生动作已登记或可能已发出 | 协调员／目标维护者阻止新动作，按原 action 核实际状态及效果；只有取得原生停止回执才声明停止。撤 grant 或移除策略文件不会停止进程 |
| 结果仅在协调核心持久化 | 保留版本及原 event。需要回传时由维护者明确保留该件必要的查回／入队权限；原生通道不可用不应要求再次执行业务。过早撤掉桥 grant 会阻断这一步 |
| 结果已安全进入桥 outbox（`PENDING`） | 入队时已按当时有效 grant 校验并保存。原 collector 后续补传不再次依赖该 grant；撤 grant、关闭原生通道或取消任务均不删除或撤回这份结果 |
| VPS 已有结果（本地 `SENT` 附回执） | 原读取方可按需查询精确版本/hash。专门的送达核验可另记 ACK。已发布版本不可覆盖。撤销准入不撤销服务端历史或读确认 |

bridge 的 `lookup_report` 仍要求当前有效 grant；撤权后查不到或被拒绝不能说明 outbox 已清空。若必须阻止尚未发出的传输，应由原 collector 维护者在获准的运行窗口暂停其唯一网络写者，并核对远端与本地原记录；该操作会影响其他待补传项，不能作为默认单件撤销步骤。当前没有逐条删除／撤回 outbox 的公共接口，不直接改 SQLite，不丢弃审计或换 OAuth／数据库来清理未知状态。

临时准入收尾应记录：谁负责停止新动作、谁核在途状态、谁确认该件结果进入哪一层、哪些最小权限何时撤销，以及保留的 UNKNOWN。已持久结果的传输责任继续归原 collector，业务取消和结果内容的解释继续归原负责人及授权方。

## 验收清单与记录边界

- **离线合同**：旧 grant 不能收目标、探针不能业务、来源/hash/代次错绑拒绝、目标与查询结果分离、多版本稳定重传、WAIT 不能完成目标。使用本仓合成测试；不得使用真实 job、密钥或音频。
- **运行能力**：在所属仓验证真实组织工具的实现、范围和预算，以及原生入口冻结配置和 UNKNOWN 恢复；工具名相同不等于实现相同。此证据独立于 Mailbox 连通。
- **单件运行**：另在批准窗口取得真实负责人 `ACCEPTED`、下一检查时间及原 job 的精确结果回读；`ADMITTED`、原生 `SUBMITTED` 和本机 `PENDING` 分别记，不合并成接手。
- **业务完成**：只认符合原目标验收条件的 `GOAL_UPDATE`。`COORDINATOR_WAIT_REPORT` 不能声明完成；外层 `REPORTED_COMPLETED` 仅表示这一份报告提交层的状态。要求独立听检时须有不同审者、精确范围与真实听辨原件，ASR 和技术计数不能替代。
- **收尾**：保留原 ID、版本、摘要、实际观察时间、拒绝／未知与撤权回执。文档、测试和 PR 合并不写成宿主已经启用或业务已经验收。

桥端接口实现与合成覆盖见 [coordinator_port.py](../mac/coordinator_port.py)、[目标合同测试](../tests/test_coordinator_goal_port.py)；运行状态仍以 [verification.md](verification.md) 中各层实际证据为准。
